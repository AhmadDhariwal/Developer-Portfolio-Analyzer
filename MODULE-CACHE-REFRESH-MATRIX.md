# Module-by-Module Cache & Refresh Matrix — Developer Portfolio Analyzer

This document covers every frontend module (Public, Auth, Developer, Notifications, Recruiter, Admin, Super Admin, Core/Navbar) and all `22` backend domain modules (+ Workflows sub-routers `/api/analysis`, `/api/workflows`, `/api/preview`).

**Legend:**  
- **SPA Nav:** Navigating away and returning within the same Angular tab without reloading.  
- **F5:** Browser normal reload (clears JS heap memory, preserves `localStorage`, sends `If-None-Match` where `ETag` exists).  
- **Hard Reload (`Ctrl+Shift+R`):** Bypasses browser HTTP cache only; **preserves `localStorage` and does NOT bypass backend memory/Redis/Mongo caches**.  
- All findings below are **Verified Source Behavior**; scheduled job durations are **NOT MEASURED**.

## 2. Detailed 14-Scenario Lifecycle Analysis by Group

### 2.1 How the 14 Events Behave Across Client-Cached vs. Server-Cached Modules

| Scenario | Client `localStorage`-First Modules (`Recommendations`, `Weekly Reports`, `Profile`) | Client In-Memory-Cached Modules (`GitHub`, `Jobs`, `News`, `Notifications`, `Support`, `RecruiterHub`, `Navbar Orgs`) | Backend-Validated-on-Entry Modules (`Dashboard`, `Resume`, `Skill Gap`, `Courses`, `Career Sprint`, `Interview Prep`, `Scenario`, `Integrations`, `Public Portfolio`, `Admin`, `Super Admin`) |
|---|---|---|---|
| **1. First opens page** | Reads `localStorage` (`24h` / `15m` / `5m`). Calls backend only on miss or `signalHash` mismatch (`Recommendations`). | Calls backend (first run populates service Map / `shareReplay`). | Always calls backend (`Dashboard` double-reads Mongo; `Courses`/`Skill Gap`/`Interview Prep`/`Public Portfolio` hit backend L1/L2/L3 caches if warm). |
| **2. Navigate away & return** | Serves `localStorage` (`0` HTTP) unless an in-tab mutation invoked `clearDeveloperSignalCaches()` / `clearProfileCache()`. | Serves in-memory Map / `shareReplay` (`0` HTTP) if within TTL (`24h` GitHub, `30s` Jobs, `15s` News/Notif, `60s` Support, `∞` RecruiterHub). | Re-mounts component and calls backend (`Career Sprint /current`, `Dashboard`, `Courses`, `Skill Gap`, `Resume`, `Admin`, `Super Admin`, `Public Portfolio`). |
| **3. Normal reload (`F5`)** | **`localStorage` survives!** Serves stale `localStorage` with `0` HTTP if unexpired. | In-memory Maps destroyed -> calls backend. Backend hits L1/L2/L3 caches. | In-memory component state destroyed -> calls backend (`Dashboard` eligible for HTTP `304` via `ETag`; others `200` from backend cache/DB). |
| **4. ## Implementation addendum — 2026-11-17

GitHub initial/navigation/reload and Refresh Data use saved-only reads. Recommendations display eligible browser results while revalidating on the server; completed service payloads no longer suppress backend revision checks. Weekly Reports page entry forces GET latest/history revalidation. Profile page entry forces a saved-profile read. These changes do not equate browser hard reload with Redis bypass.
