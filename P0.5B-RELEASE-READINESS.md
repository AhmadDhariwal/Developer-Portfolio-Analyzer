## 5. Deployment & Rollback Prerequisites

### Pre-Deployment Order (Staging First)

1. **Provision Backup Before Changes:** Take a point-in-time snapshot (`mongodump` / Atlas snapshot) of staging/target MongoDB; verify restore into an isolated test DB cleanly.
2. **Provision Staging Secrets & Topology:**
   - MongoDB **replica set** URI with `?retryWrites=true&w=majority` and sufficient volume free space (`>524 MB` min per MongoDB index-build floor; recommended `>=20 GB`).
   - `NODE_ENV=production`, `SECURITY_STRICT_ENV=true`, `AUTH_COOKIE_SECURE=true`, random `JWT_SECRET` (`>=32` chars), explicit **`SETTINGS_ENCRYPTION_KEY`** (copied/preserved across upgrades so encrypted `PlatformSettings` integration keys decrypt), production `FRONTEND_BASE_URL`/`CORS_ORIGIN`.
   - Managed TLS Redis (`rediss://...` or `UPSTASH_REDIS_HOST` + `UPSTASH_REDIS_PORT` + `UPSTASH_REDIS_TOKEN`, leaving local `REDIS_URL` empty), B2 distinct `images` + `resumes` bucket credentials, SMTP/SendGrid, OAuth callbacks, and AI keys.
3. **Database Schema & Index Application Order (Critical):**
   - Because `Job`, `RecruiterMatch`, `RecruiterShortlist`, `AuditLog`, and `User` define unnamed schema indexes while `ensureRecruiterIndexes.js` uses `recruiter_*` names: **run initial Mongoose schema `createIndexes()` (or verify existing collections) BEFORE `ensureRecruiterIndexes.js --dry-run` / `--apply`**, and verify `ensureCareerSprintIndexes`, `ensureNewsTopicIndexes`, `migrateNotificationIndexes --apply`, `inspectIntegrationIndexes --apply`, and `migrateScenarioSimulationUniqueIndex` dry-run cleanly. Never run `cleanupInvalidMemberships.js` or `migrateSavedPreviewIndexes.js` without prior read-only duplicate/invalid inspection and backup.
4. **Deploy Frontend & Backend + External Cron:**
   - Serve `frontend/dist/frontend/browser` behind the same origin as `/api` (or inject `window.__DEVINSIGHT_API_ORIGIN__`).
   - Schedule external cron/job runner for `backend/src/scripts/retryAccountDeletionCleanup.js` and `retryStorageCleanup.js` (not started by `backend/index.js`); set `WEEKLY_REPORT_PROCESS_ROLE=api` on API pods if running a separate `weeklyReports` worker.

### Rollback Procedure

- **Quick Maintenance Freeze:** Toggle Super Admin `maintenanceMode = true` in `PlatformSettings` (propagates across workers within ~2s via Redis revision token / 30s Mongo TTL; `/api/auth` & `/api/super-admin` remain accessible).
- **Graceful Process Drain:** Send `SIGTERM` cleanly (`15s` shutdown deadline in `backend/index.js`); workers persist durable Mongo leases (`IntegrationJob`, `EmailDeliveryJob`, `StoredAsset`, `AccountDeletionCleanup`, `WeeklyReportCoordination`) so incomplete jobs resume safely.
- **Artifact & Data Rollback:** Redeploy prior known-good container/Git release (`c46116ec` / prior release tag) **keeping the same `SETTINGS_ENCRYPTION_KEY` and `JWT_SECRET`**. Backward schema compatibility holds because P0.1–P0.5B added no breaking schema removals; only restore DB snapshot if destructive manual cleanup scripts were run.
