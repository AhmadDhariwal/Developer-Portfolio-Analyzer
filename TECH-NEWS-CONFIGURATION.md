# Tech News configuration and deployment

This guide describes the catalog implementation added in October 2026. Historical reports under `backend/verification/tech-news` and `frontend/verification/tech-news` remain evidence of earlier versions. The current local runtime audit is `backend/verification/tech-news/runtime-audit/REPORT.md`; production gates remain documented in `backend/verification/tech-news/CATALOG-FINALIZATION.md`.

## Configuration inventory

`backend/.env` and `backend/.env.example` have one ordered News section with **102 keys**, generated from `backend/src/config/newsEnvCatalog.js`: the preceding 81 keys plus 21 additions. Every assignment has an immediate explanatory comment and restart guidance. The local environment is ignored by Git and must remain private. Existing assignments and credentials were preserved. The example contains empty credential placeholders.

These defaults are application ceilings, not grants of content rights. Contracts requiring less than one hour or deletion-event processing need additional support before activation.

`NEWS_DISCOVERY_PREWARM_TOPICS` is retained for environment compatibility and ignored. Its old value is preserved locally; new examples leave it empty. Taxonomy names classify articles and constrain public upstream repository/feed URLs; they are not mandatory prewarm candidates. `NEWS_QUERY_STALE_TTL_MS` still governs the legacy snapshot cache, not the catalog history window.

All changes require a backend restart. Startup rejects invalid values, unknown News keys, duplicate assignments and inverted cache TTLs. Missing optional keys and the deprecated topic setting are reported by key name without values. Missing keys use bounded runtime defaults; they do not silently grant approval. The configuration tests check inventory parity and immediate comments. To reorganize another installation, privately back up its environment and run `node backend/src/scripts/organizeNewsEnv.js`; it asserts existing parsed assignments remain equal.

The explicit example assignments are configuration recommendations, not always the missing-value fallbacks. Comments now document actual absent-variable behavior: discovery/prewarming require an explicit `true`; adapters other than broad HN/DEV default to unapproved with zero budgets; missing per-adapter intervals default to 1200000 ms; missing shared budgets sum the effective family budgets. Existing configured assignments are preserved. `NEWS_DISCOVERY_RESULTS_PER_PROVIDER` controls HN/DEV keyword request sizes; GitHub/RSS caps are independent. `NEWS_QUERY_MEMORY_ENTRIES` bounds legacy discovery memory; the catalog query cache has its own fixed 128-entry ceiling. All 102 keys, consumers, validation constraints, template values and missing-value defaults are inventoried in `backend/verification/tech-news/runtime-audit/runtime.json`. The only intentionally unused runtime control is the deprecated `NEWS_DISCOVERY_PREWARM_TOPICS`.

Keep `MONGODB_URI` and `REDIS_URL`, or `UPSTASH_REDIS_HOST`/`UPSTASH_REDIS_PORT`/`UPSTASH_REDIS_TOKEN`, in their existing global sections. Upstash uses the native Redis TLS endpoint and database password, not a REST bearer token. Obtain them from the existing database's connection panel. All workers must share the same Redis deployment. Redis Cluster hash-slot compatibility is not established; use the supported non-cluster Upstash/native Redis configuration.

Existing environment values take precedence. Broad HN/DEV reservations protect the search adapters' configured daily/monthly headroom. Quota counters include failed transport attempts and are never refunded.

No restricted provider was enabled, no credential was replaced, and no new paid subscription was purchased. Normal scheduled collection starts only when the ingestion flag, platform news setting, content approval, credentials where required, budgets, intervals and Redis admission all permit it. Search does not use NewsAPI/GNews/Reddit credentials.

## Safe rollout and indexing

1. Review source rights and retention; keep restricted/unreviewed sources disabled. Back up the application database using the established deployment process.
2. Stop collection while applying the upgrade. Run `node backend/src/scripts/migrateNewsCatalog.js` for a read-only inventory. It lists declared additive indexes and counts eligible metadata in the exact public pool and legacy public discovery namespace. Private ranking documents and saved records are excluded.
3. Review the unique canonical identity, expiry TTL, published-date/canonical tie-breaker, technology/date, search-term/date, source/date and category/date indexes against deployed MongoDB explain plans and storage capacity. The implementation uses ordinary MongoDB multikey indexes, not Atlas Search. The isolated MongoDB 8.2 explain evidence is retained in `backend/verification/tech-news/catalog-results.json`; it is not a production-load benchmark.
4. Apply the reviewed migration with `node backend/src/scripts/migrateNewsCatalog.js --apply`. It creates only declared indexes, tightens catalog expiry to current source limits, and idempotently upserts eligible legacy public metadata. It never calls `syncIndexes`, drops indexes/collections, deletes saved/history records or rewrites legacy snapshots. Index creation is not automatic on the new model. Ingestion must not start before the unique index exists. TTL cleanup is asynchronous; readers enforce expiry immediately.
5. Restart the backend with `NEWS_INGESTION_ENABLED=true` on an active worker process and the existing platform news setting enabled. Broad work evaluates every minute and is admitted separately by each provider's configured interval; it is not one daily request. Discovery ticks every five seconds, with token-owned worker/ingestion leases. No deployment process-manager manifest is provided by this repository.
6. Validate native hosted Redis writes using isolated owned test keys and approved deployment procedures. Validate live worker heartbeats, quota behavior, index plans, provider response contracts, pagination, history, personalization, both refresh actions and no-newer states on the deployed version. These actions were not performed against production in this task.

Retention changes take effect in reader predicates after restart; run the reviewed migration to tighten existing persisted TTL dates. A revoked content approval immediately excludes that source from catalog queries. Contract-specific deletion obligations still require an operator cleanup/review; changing a flag is not proof of upstream deletion compliance.

## APIs and operational capacity

The authenticated `/api/news` envelope, saved endpoints and history fields are preserved. Ordinary GETs browse stored data. The updated client submits `discover=true` only for an explicit changed search; `refresh=true` requests a governed provider check; `bypassCache=true` re-queries stored results and suppresses admission. Page > 1 never admits a job, including a request carrying a refresh flag. Older clients still receive stored data; clients relying on implicit search admission should adopt `discover=true`.

Explore paginates indexed catalog matches in MongoDB. For You ranks a bounded recent candidate set using canonical Developer Context and the existing 50/30/20 formula; no technology input is shown. Over the configured ranking limit, the personalized total describes the candidate window and telemetry reports `rankingLimited`. Explore remains independently pageable. Trending's popularity sort can require an in-memory Mongo sort within the bounded date window; no unnecessary popularity compound index was added without production explain evidence. Deep offset pagination and compound category/source/text combinations require deployed load review.

Catalog response caches store only public candidates, never account ranking or profiles. They use five-second absolute expiry and keys containing the durable per-technology version (global version for general/free-text queries), source policy and normalized filters. Each request checks the Mongo version before reuse, favoring consistency over eliminating all Mongo reads. Redis failure falls back to Mongo; catalog failure falls back to the existing bounded pool/topic snapshots and reports `catalogUnavailable`. Historical coverage is unavailable during that fallback. Legacy compatibility snapshots still mirror bounded article metadata for existing consumers such as Dashboard; the unique catalog is the authoritative history/search store, and no per-technology collection is created.

The existing metrics registry exposes `dpa_news_ingestion_total`, `dpa_news_catalog_reads_total`, `dpa_news_provider_admissions_total`, `dpa_news_queue_delay_ms`, `dpa_news_catalog_articles` and `dpa_news_topic_articles`. Catalog size/coverage gauges update during adaptive evaluation; they can be absent/stale when it is disabled. Aggregate across workers for counters and use the latest catalog gauge. No raw queries, account identifiers or profile data label metrics.

There is no guarantee of exhaustive coverage. Result caps, source quotas, retention, reviewed repositories, strict RSS parsing and available upstream search routes bound collection. Article count grows with unique accepted URLs over the retention window, rather than users multiplied by topics. The catalog does not backfill history beyond metadata already available from sources or legacy caches.

## Discovery status and source-check eligibility

Explore retains available cards while an admitted job is queued, searching or saving. The inline status panel animates only during the existing bounded active-check window. Up to four 20-second catalog-only revalidations adopt newly persisted data; when the window ends or polling is paused, the panel explains that work may continue and offers Refresh Results. A completed or blocked state does not retain a spinner. Reduced-motion preferences disable animation.

The source-check button says "Check again in …". Its deadline is the maximum of backend `enrichment.nextEligibleAt` and request `Retry-After` pauses, not an article-arrival timer. Feed `serverTime` corrects browser clock skew; HTTP `Date` anchors absolute Retry-After values. Optional `eligibilityReason` distinguishes the manual successful-check interval, provider admission and query freshness. Source quota/interval/account-budget reasons remain in `reason`. Refresh Results stays a separate stored-catalog read and never spends provider quota.

## Verified operator activation notes

Credentials alone do not establish entitlement. The October runtime audit preserved every approval and quota. NewsAPI and GNews keys are present locally but those sources remain unapproved with zero budgets. Reddit additionally lacks its OAuth token and identifying user agent. Lobsters has numeric budgets but remains unapproved; Cloudflare has neither approval nor nonzero budgets. For each source, the operator must first establish its deployment/content/retention rights, then deliberately set the existing approval, reviewed retention and nonzero bounded budgets, add required credentials, and restart. No counter reset or quota increase is part of activation verification.

The currently retrievable [GNews terms](https://gnews.io/legal/terms-of-service) limit unpaid access to non-commercial use; this supersedes the earlier inability to retrieve detailed terms in the provider table. [NewsAPI terms](https://newsapi.org/terms) exclude staging/production from the Developer plan. Reddit requires approved access under its [Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy), with a separate agreement for commercial use under its [Data API terms](https://redditinc.com/policies/data-api-terms). Provider contracts and token/deletion obligations must be checked for the actual deployment; no entitlement was inferred from local configuration.
