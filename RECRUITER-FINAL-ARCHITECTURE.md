# Recruiter final architecture

The Recruiter Hub uses an Angular lazy module with routed pages, reusable presentation components, and feature services over the shared ApiService. Express routes enforce recruiter role and organization context before controllers invoke services and Mongoose models. Legacy routes remain mounted alongside the Hub.

| Phase               | Ownership and change                                                                                                                                                                                                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ranking             | Matching utilities own the six configured weights, feature normalization, explanations, and Hub record mapping. GitHub now contributes its 15% weight when available. The breakdown identifies unavailable GitHub, skill, and project evidence. Hub skill and experience fields use absolute signals. |
| Hiring data         | Recruiter job operations scope by organization and owner. Shared job lifecycle logic removes linked match and shortlist records transactionally. The legacy Admin job service retains organization-wide management.                                                                                   |
| Candidate discovery | Matching service applies the global visibility setting and active developer opt-in at the User query. Hub detail and pipeline hydration resolve canonical User IDs in batches. Legacy IDs remain accepted for lookup where linked to an active Candidate record.                                      |
| Invitations         | Auth claims a pending invitation and saves the account, organization membership and optional team membership in one MongoDB transaction. The canonical recruiter profile handles onboarding.                                                                                                          |
| Reporting           | Hub aggregates canonical Jobs, RecruiterMatch, RecruiterShortlist and AuditLog records. Admin and Super Admin reporting consume canonical candidate analysis and matching sources.                                                                                                                    |
| Finalization        | Changed-file inventory, verification commands and unresolved items are in the final acceptance report.                                                                                                                                                                                                |

Transactions require MongoDB replica-set or sharded deployment support. The implementation was evaluated on a disposable single-member replica set. Candidate search and analytics still use bounded in-memory candidate pools. Large-tenant pagination and capacity remain open.
