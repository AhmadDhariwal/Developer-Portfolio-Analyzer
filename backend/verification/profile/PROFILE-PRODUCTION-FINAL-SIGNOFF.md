## Changes and request-flow security

The staged candidate implements MongoDB `integrationgovernancestates` as the single admission authority for Profile/Portfolio quotas. The preserved upload thresholds, windows, identities, 429 responses and `Retry-After` behavior remain in force. Redis is optional for those migrated paths; it remains untouched for other modules. Admission-store errors return 503, without a local counter fallback. The existing endpoint-by-endpoint middleware order, database/Mongo authority boundaries, identities and limitations are detailed in [the request-flow governance report](../architecture/REQUEST-FLOW-GOVERNANCE-FINAL.md).

Fresh local checks covered concurrent boundaries, workers and restart, forwarding-header spoofing, authenticated multipart upload paths, parser/storage/delivery bypass prevention, and recovery after a Mongo disconnect. The final bounded local admission sample was 12 Mongo calls, median 15.835 ms and maximum 31.4 ms on a disposable loopback replica set. This measures local warm-path behavior only; it does not predict production Mongo latency or capacity. Mongo majority transactions add a shared durable write cost per admission. The TTL index is cleanup only; logical expiration determines quota, so TTL monitor delay does not grant extra quota.

The active storage runbook now documents a coordinated handover: completely drain old Redis-backed Profile workers before Mongo-backed workers serve the quota. Never mix both populations. Preserve both counter sets for rollback; before reverting, drain all Mongo workers and account for Mongo quota consumed until each affected window expires. No counter resets or quota replay are allowed. Redis recovery remains relevant only to unchanged Redis-authoritative modules.

## Profile avatar save follow-up

After this sign-off was drafted, selecting a Profile photo was changed to create only a local preview; it does not call the upload API or alter the saved avatar. A transient AuthService stream updates the Profile settings preview, navbar, and sidebar together without writing a blob URL to local storage. **Discard** restores the saved photo across those views; **Save changes** uploads the pending file after any profile fields have been saved. A failed upload keeps the saved photo and leaves the preview available for retry. A full-page loader blocks interaction during save, and a route guard prevents module navigation until the request settles. Clicking the settings photo opens a large, contain-fitted preview that closes with Escape or the close/backdrop controls. TypeScript checking and the production build pass after these changes. Unit and fresh browser suites were not rerun for this follow-up.
