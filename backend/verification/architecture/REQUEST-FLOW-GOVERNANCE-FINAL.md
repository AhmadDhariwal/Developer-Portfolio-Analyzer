## Global execution order

`backend/index.js`: skill-gap timing marker → Helmet → CORS → global API limiter → request context → bounded JSON/webhook-byte capture (100 kb) → bounded URL-encoded parser (100 kb) → maintenance guard → `/uploads` access/storage/static chain → HTTP metrics → optional request logging → audit middleware → mounted route/router guards → controller/service → error middleware. Multipart bodies are not parsed by the global JSON middleware. CORS preflight may terminate before later middleware. Maintenance exemptions remain unchanged. Redis startup is optional and bounded to four seconds; no new startup dependency was added.

The global limiter precedes persisted authentication. Its verified JWT identity is only an ingress quota key; it does not authorize anything. Route `protect` independently verifies issuer/audience/session revision, loads the Mongo account and checks active status. Owner predicates and storage ledger checks remain authoritative. Existing authentication catches a failed account lookup as authentication failure; a complete database outage is therefore not guaranteed to reach admission or produce its 503. A failure specifically in Mongo admission produces 503 before protected work, as tested.

## Admission architecture and conservation

| Approach                                              | Assessment                                                                                                                                                                                                                          |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Redis-primary → empty Mongo/local fallback            | Rejected. A worker/store switch can grant another allowance; restarts and simultaneous stores permit split-brain. Retry-After alone does not transfer state                                                                         |
| Redis-primary with durable mirrored Mongo reservation | Could conserve quota only if every allowance is committed to the durable authority before work. Redis cannot independently grant credit; this adds reconciliation and another failure surface without avoiding authoritative writes |
| Mongo-authoritative, optional Redis cache             | Chosen. One durable budget per policy/identity/window for every worker and Redis state; reuses tested initialization, transaction retries, unique `_id`, majority writes and logical expiry                                         |

`requestWindow` is an additive export in `integrationMongoGovernanceService.js`. It uses the existing connection, collection and transaction helper. Integrations' original admission/action/cooldown code and policy defaults are unchanged. Keys are `public-portfolio:v3:rate:<operation>:<SHA256(subject)>:<floor(now/windowMs)>`; they cannot collide with existing integration keys. There is no new collection/schema/dependency. Built-in `_id` uniqueness handles first-writer races; duplicate insert races retry the whole transaction. Existing 2-second transaction retry budget/1-second commit bound remain; collection/index initialization uses bounded commands and is cached per connected DB.

Every count is read and replaced in a snapshot/majority transaction. Contending workers retry rather than admitting from stale reads. Values saturate at limit+1, preserving denial and reducing repeated rejected writes; a saturated request still incurs a bounded point read/transaction. Invalid persisted counters fail closed. Absolute bucket expiry is checked in code, independently of TTL deletion. The existing `governance_expiry` TTL index reclaims governance state, never stored-asset/deletion receipts. No TTL is added to durable storage work.

Original policies: view 60/min; resume download 10/min; analytics 30/min; mutation 20/min; shared avatar/portfolio/B2 résumé upload 10/hour; sender contact 3/hour; recipient slug 20/day. Existing authenticated account, `req.ip`, and recipient-slug identities are preserved. Filesystem uploads now join the same existing upload budget; public preview parsing uses that policy with IP identity. No caller header/body user ID or local allowance is trusted. Sender then recipient counters remain sequential: recipient denial conservatively spends a sender attempt, as before; no refund enables extra delivery. Profile has no additional cooldown state beyond fixed windows. Integrations cooldowns are unchanged.

Allowed responses retain `RateLimit-Limit`/`RateLimit-Remaining`; exhausted quota returns 429, remaining 0 and at least one second of Retry-After until the bucket ends. Mongo admission error returns sanitized 503 and Retry-After 30 before multipart/storage/mail. The previous non-strict Portfolio fallback paths now also fail closed if admission fails; Redis failure alone never changes their authority. No refund occurs after an uncertain downstream result.

## Security, privacy and observability

The focused suite checks atomic boundary admission across two independent OS processes, process restart without counter loss, Redis healthy/unavailable/healthy fixture transitions with zero Redis admission access, expired-but-present Mongo rows, disconnect/reconnect retention and required indexes. It exercises real JWT/account reads, real multipart/PDF parsing, actual Mongo ledger/selection transactions and fixture S3 for avatar/portfolio/résumé uploads. It injects admission failure while authentication remains available, uses malformed multipart fields to demonstrate rejection before parser execution, and checks zero additional storage/mail calls. Shared exhaustion blocks both storage drivers; sender and recipient exhaustion block delivery. Anonymous preview parser failure is blocked by admission. Spoofed forwarded headers must not rotate IP buckets when proxy trust is disabled.

Existing Profile/B2/regression fixtures cover ownership/privacy/session revision, replacement rollback, durable cleanup/restart and legacy readers; some older fixtures intentionally stub admission to isolate storage. The new suite supplies the missing combined real-admission upload coverage. SMTP and S3 are fixtures; this run does not send email or access real B2/Upstash. Previous live-B2 evidence remains historical, not claimed as a fresh live upload run.

New low-cardinality Prometheus metrics: `dpa_portfolio_admission_total{operation,outcome}` and `dpa_portfolio_admission_duration_seconds{operation}`. Outcomes distinguish allowed/limited/unavailable; operation labels use a fixed allowlist. No user/IP/slug/content/credential is logged or used as a metric label. SHA-256 keys are pseudonymous, not anonymous; restrict collection/backup access and retain only through normal governance TTL/backup policy. Existing route status/latency metrics remain available.

Express owns proxy identity. The application currently does not configure `trust proxy`; direct loopback spoof resistance is testable, while the deployed proxy allowlist/header sanitation remains an operator gate. Preserve the original IP identity, including its current IPv6 behavior, rather than silently changing quota policy. All workers must have synchronized clocks and matching policy/software; fixed windows retain the existing clock-based contract.

Mongo TTL deletion is asynchronous, so correctness must never depend on immediate deletion: [MongoDB TTL documentation](https://www.mongodb.com/docs/manual/core/index-ttl/). Transaction contention and retries must be tested under the actual deployment: [MongoDB transaction production considerations](https://www.mongodb.com/docs/manual/core/transactions-production-consideration/).

## Rollout, rollback and remaining gates

1. **Quota-conserving handover:** drain/stop every old Redis/local-governed Portfolio worker and prevent legacy admission before enabling new workers. With no reviewed exact transfer, wait until all outstanding absolute windows expire: up to the remaining daily recipient window (conservatively 24 hours since the last old admission). Do not run mixed versions. Redis being unreadable is not evidence of an empty budget. No automatic transfer/deployment is performed.
2. **Rollback:** Mongo remains the authority for an application rollback that retains this middleware. Returning to legacy Redis admission requires the same full drain and reviewed budget transfer/expiry; simply changing environment or restarting old workers is unsafe. Never clear counters to recover service.
3. **Production Mongo:** verify transaction-capable topology, majority durability, primary read routing, existing built-in `_id` and exact non-partial `{expiresAt:1}`/`expireAfterSeconds:0` TTL contract, app index permissions/provisioning, synchronized clocks, retry/commit deadlines, backups and real outage/failover behavior. No production index or collection was changed here.
4. **Load and alerts:** measure p50/p95/p99 admission and contact contention under expected fleet/anonymous traffic; alert on unavailable outcomes, 429 surges, latency, transaction retries and governance collection growth. Keep Mongo capacity separate from expensive application query load. Serial local tests are correctness evidence, not a soak result.
5. **Existing scope gates:** global/auth/login and Interview/News/Jobs-read local fallback quotas remain unsuitable as mandatory fleet-wide controls. Their shared-authority migration requires a separately scoped authentication/module change preserving those policies. Existing Scenario explicit single-instance mode and GitHub/generic-cache coordination findings also remain documented. This prevents declaring the entire application production hardened from this Profile-focused change.
6. **Profile/B2 operations:** retain least-privilege key/retention review, storage/index provisioning, one bounded cleanup schedule/alerts, explicit B2 activation, original filesystem mounts/readers, same-origin HTTPS/Secure cookies/CORS/proxy checks, JWT/all-worker consistency, external delivery/provider and logout/privacy policy gates from the existing handoff. Redis recovery is no longer the gate for these migrated routes; it remains relevant to unchanged Redis-authoritative modules.
