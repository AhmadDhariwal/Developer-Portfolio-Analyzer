# Audit before implementation

Submission sends the selected skill and free-text question through the authenticated controller to answerCustomInterviewQuestion. It checks cache, verified Mongo exact/similar answers, the verified catalog, and owner-scoped custom history, then calls the shared provider manager. Existing validation covers shape, topic/relevance, trust labels and architecture fields, but not completeness against individual user requirements. The custom prompt uses one general template. Cache returns bypass validation; private history checks approval but has no coverage version. Independently validated requirements/evidence are absent. Incomplete topical answers can therefore be saved and reused. The Angular card displays all existing fields but renders explanation as plain text and the entire example as a code block.

Plan: add generic deterministic intent analysis plus a separate lightweight semantic evaluation for practical/multi-part answers. Share existing deadlines and actual-call budgets across generation/evaluation/one repair; never nest evaluation inside held provider admission. Require literal answer evidence per requirement and structural checks, not generator self-certification. Gate cached, verified and private reuse; keep historical snapshots immutable. Store server-produced quality attestations in existing sourceMeta, render existing strings safely, and finish tests/build/formatting/cleanup. No schema/API fields or dependencies are required.
