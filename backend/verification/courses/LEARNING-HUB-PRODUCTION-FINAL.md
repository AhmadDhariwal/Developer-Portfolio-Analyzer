### My Learning: traced failures and fixes

The original user-session network trace is **BLOCKED**: Computer Use ended because it could not establish the existing browser URL with sufficient confidence. It was not bypassed. The following are reproduced defects using the committed pre-fix code, real JWT middleware, a disposable Mongo replica set and local HTTP requests—not a claim that the inaccessible original session had the same stored row.

1. **One incomplete saved snapshot failed the entire list.** `listProgress()` mapped every row through `dto()` → `snapshot(row.course)`. A historical row without `course` threw a TypeError when reading `course.id`. JWT and admission succeeded, Mongo returned the owned rows, then the progress controller returned 503 and the store disabled saved actions. Replaying the committed implementation reproduces that network response. The fixed DTO keeps the identity, notes, status and explicit progress, marks unavailable details with `recoveryRequired`, blocks unavailable links and returns the list with an integrity count. It does not drop rows, substitute invented course metadata, rewrite snapshots or return an empty list on storage failure. Existing incomplete records remain editable; concurrent removal returns 409 rather than silently recreating a record.
2. **Discover and My Learning shared a quota bucket.** The old `/my-learning` route used `admitCourseRead`, consuming the same owner/IP read windows as Discover. It now has its own Mongo-authoritative `learning-read` bucket. A one-request quota fixture verifies Discover 200 → 429 while My Learning still returns 200. Permissions and admission remain enforced.
3. **Database failures could look like expired JWTs.** `protect()` caught user-lookup failures inside the JWT error handler and returned 401. A valid token could therefore produce a false session-expired message. User-store failures now return 503, `AUTH_STORAGE_UNAVAILABLE` and Retry-After; invalid identities, invalid/expired tokens, revoked sessions and inactive accounts retain their authentication checks. User and progress operations have bounded five-second database budgets. A disposable primary step-down verifies recovery without losing notes/progress or falsely expiring the session.
4. **A refresh could overwrite a committed mutation.** Both progress views now detect a learning revision change while their read is pending and reload the server state rather than applying an older snapshot. A delayed-read/committed-write test preserves the new notes and 27% progress. Failed reads and writes retain previously confirmed data, remain visibly unavailable, and recover through retry. My Learning errors do not replace Discover's course grid.

Progress reads remain uncached, private and owner-scoped. Redis and course-provider availability are not prerequisites for My Learning. The new `user_course_recent` index supports owner-wide `{updatedAt:-1,_id:-1}` pagination; the existing status-specific and unique owner/course indexes remain. Real explain output verifies an indexed read without a blocking sort. ### Implemented architecture and boundaries

The new authoritative `shared_course_catalog` collection stores normalized **raw courses**, independently of `AnalysisCache` personalized projections and `UserCourseProgress` private snapshots. Raw publication strips owner fields, recommendations and scores. Canonical URLs/identities are deduplicated before publication. Saving can resolve a durable shared course by its indexed ID; existing private snapshots remain editable after archival and retain their identities, notes, explicit progress and historical URL.

Request flow is JWT/Mongo admission → current profile/Skill Gap v9 evidence and catalog revision → validated private projection cache → on a miss, canonical topic → shared raw memory/Mongo coverage → filter and deterministic personalization → global ranking → pagination → response. Private projection caching is an optimization after evidence/revision validation. Redis remains optional for those projections; raw catalog authority and distributed coordination reside in Mongo. Redis is never required to fetch an existing shared topic.

- Versioning: raw policy `shared-courses-v1`, curated inventory SHA-256, discovery/ranking policy revision **3**, existing private `courses_pool_v6_evidence` contract preserved. Catalog audit revisions invalidate private namespaces, with a bounded 30-second revision cache. Provider credential fingerprints invalidate incompatible raw coverage without exposing credentials.
- Bounds: 45 reviewed topics plus four stack fallbacks, at most **49 YouTube coverage documents × 40 courses = 1,960 raw slots**, one curated document capped at 200 courses, one provider-control document. Unknown free text filters a stack pool rather than creating unbounded paid queries. No durable catalog TTL deletes canonical records; finite topic slots are refreshed in place. Historical progress is stored separately.
- Freshness: successful raw coverage is fresh for six hours, usable stale for at most seven days; empty coverage has a ten-minute negative TTL. Failure backoff is 20–60 minutes. Raw memory is bounded to 50 entries, fresh for at most 30 seconds, with five-second stale admission to suppress repeated refresh attempts. Curated memory is one bounded inventory. Stale private projections expire within 15 seconds and never outlive the raw source deadline, including Redis and completed-lease reuse.
- Coordination: atomic Mongo server-time topic leases and fencing tokens publish the whole raw coverage document. A late owner cannot overwrite a successor. Crash leases expire after 45 seconds. Four distributed provider slots, four local raw builds, at most 200 cold waiters and 200 local personalized builds bound work. Publication is idempotent. Private pool leases and per-user/IP quota windows also use Mongo server time; a two-day worker clock shift could neither reset quota nor steal a lease.
- Cost control: each admitted pipeline reserves up to two official search requests plus one details request. Default admission is **48 pipelines per rolling 25 hours**, hard capped at 49, across workers; failed/crashed reservations are not refunded. This covers Pacific DST quota days. The provider-wide breaker and quota reservations survive restarts. An operator must allocate this allowance alongside any other applications sharing the Google project.
- Recovery/API behavior: bounded provider HTTP and Mongo operations, persistent breaker, exponential backoff, stale-while-revalidate and durable negative caching. Catalog storage faults use retryable 503; user/IP denial uses 429; both include Retry-After. All Courses can retain curated alternatives when YouTube refresh admission is deferred. A fresh shared topic is reused even when another user requests refresh.
- Maintenance: hourly scheduled batches audit four allowlisted public curated URLs, with bounded HEAD requests and manually validated redirects. No page content is ingested. Two 404/410 observations separated by the weekly audit interval archive discovery safely; 403, 429, timeouts and provider errors do not retire courses. Redirects needing review are recorded. Optional background ingestion refreshes two existing stale topic coverages per tick, under the same provider leases/budget; it is off by default. Coverage reports include overlaps, topics, providers, missing topics and audit results.
