### Proven root cause, captured before source changes

The frontend correctly passes the complete `topic=Quantum Computing` value. Backend filter normalization preserves it; taxonomy canonicalizes it to `quantum computing`. It is an unseen compound topic, so the previous `queryTerms()` split it into `quantum` and `computing`. Mongo's existing text query performs candidate-document OR matching; a document containing only “computing” qualifies, and unwinding also exposes its sibling courses. The old course-level test was `matchScore(course, topic) > 0`. That score added points for **either** word in title, topics or description. “Computing” alone therefore admitted unrelated Cloud/AWS and Scientific Computing courses. `applyCourseFilters()` receives an empty topic after this step, relying on that eligibility decision. Counts, personalized ranking and pagination consequently operated on the falsely admitted courses.

The JWT/API path is catalog-only. Its reviewed seed helper happens to be named `buildFallbackPool`, but it loads the global reviewed inventory; no generic stack-fallback branch was responsible for this defect. There was no frontend parameter truncation or cache-key collision between different topic strings. Cached pools could, however, retain the wrong eligibility result until the search policy changed.

Before modifying source, an isolated Mongo/JWT reproduction returned **58 false matches** both through direct shared-catalog search and `GET /api/courses`. This deliberately controlled dataset contained 57 synthetic AWS Cloud Computing records plus the existing reviewed Scientific Computing course. It reproduces the reported count without inspecting or modifying the user's running database. [Pre-fix requests and direct result](relevance-2026-11-06/before.json), [expected failing regression](relevance-2026-11-06/before.log).

### Eligibility before ranking, counts and pagination

- `courseCatalogTaxonomy.topicPredicate()` compiles a bounded predicate once per catalog read. Canonical technologies use verified whole-term spelling aliases, with Unicode word boundaries preventing Java from matching JavaScript. Arbitrary compound queries require the exact phrase or **all meaningful query terms within one metadata field**; generic instructional filler is ignored, while a shared word such as “computing” never substitutes for the missing subject. Course titles, explicit topics and descriptions supply the existing verified metadata evidence. Generic-only instructional queries do not admit the whole catalog.
- Quantum Computing has a small explicit contextual relation to Qiskit/qubit/qubits. These terms expand indexed candidate retrieval and qualify genuine contextual records even in separate documents containing neither “quantum” nor “computing”. They are **not** spelling aliases and do not rename Qiskit, alter the technology registry, saved IDs or progress. Generic quantum physics or AWS computing alone does not qualify.
- The new eligibility gate runs after normalization and before deduplication, source coverage, non-topic filters, totals, provider counts, ranking or pagination. Ranking retains its existing 6/4/1 search weights, soft diversity and deterministic For You scoring. The same predicate governs provider quality/worker success, avoiding false “covered” outcomes from generic overlaps. No related suggestions or stack alternatives are mixed into primary results.

Thus process memory, Redis, Mongo result projections and governed completed-pool keys cannot reuse permissive legacy results. Raw provider catalogs retain their version/freshness, so this correction does **not** force provider refetches, migrate progress or delete old records. All existing Mongo authority, cache bounds, provider budgets, leases/fencing and Redis-optional behavior remain in place.
- Zero eligible matches use the existing pending/cooldown/unavailable discovery workflow. External provider work remains scheduled/background-only and deduplicated per admitted topic. Polling and manual retry continue to read the shared catalog without bypassing quotas.
