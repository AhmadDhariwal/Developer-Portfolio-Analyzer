The invite token authorizes claiming the invitation record. An existing account must separately prove its identity with the existing verified session. Acceptance rejects incompatible active membership, affiliation, privileged account role, unavailable teams, suspended organizations and ineligible inviters. The invitation claim, organization timestamp write, seat check, user write, membership write and accepted-by attribution use a single session. Pending-only revoke and expire writes compete on the invitation record. Public JWTs are created after a successful commit. Email on invitation creation runs after commit.
