## 3. Confirmed defects and corrections

1. **Super Admin bypass on organization Admin routers.** `authorizeRoles('admin')` intentionally permits Super Admin globally. That contradicted the Admin Console route comments and organization-only contract. Added `requireAdminAccountRole`, which normalizes the account role and requires exactly `admin`, before organization context on `/api/admin` and `/api/admin-console`. HTTP tests prove Super Admin receives `403` while an organization Admin remains allowed on both route families.
2. **Suspended tenant fallback.** Organization context could accept a suspended canonical organization or resolve an owner/membership fallback without checking suspension. Canonical, owner, and membership paths now fail closed for suspended organizations; tenant role resolution also verifies organization status for direct and team-derived roles. Disposable HTTP tests cover suspended organization and team access.
3. **Incomplete/scoped analytics.** Job analytics loaded all organization job documents to count them, while invitation funnel totals were incorrectly derived from a recent sample. Jobs now use organization-filtered MongoDB facet aggregation; invitation funnel counts use full organization counts with time-aware pending/expired rules. Recent invitations remain bounded and sort deterministically.
4. **Audit activity attribution and privacy.** The console activity feed derived organization scope from current actor memberships, which could omit historical organization events or mix affiliations, and the default projection risked exposing audit payloads. It now filters directly by organization and non-deleted logs, uses the same predicate for list/count, stable timestamp/id ordering, and an allowlisted projection that excludes `before` and `after`.
5. **Concurrent team capacity and partial team assignment.** Both Admin Console and tenant team creation previously performed a count-then-create check, permitting two requests to take the final slot; Console team/member writes were also separate. They now share a transaction helper that advances the existing organization `updatedAt` field, reads capacity, then creates the team and any recruiter/manager memberships in the same transaction. The configured `maxTeamsPerOrganization` remains 10.
6. **Duplicate slug races.** Organization slug duplicate-key errors are narrowly converted to the existing safe `409`. Team duplicate-key conversion is restricted to the team slug index so unrelated membership uniqueness failures retain their original error behavior.
7. **Platform support authority.** Global support routes and service operations accepted organization Admin accounts even though tickets lack organization attribution. Route middleware and service authorization now require normalized `super_admin`; tests assert organization Admin denial and Super Admin allowance.
8. **Recruiter seat races.** Direct Recruiter creation, invitation acceptance, invitation creation, and activation used independent count-then-write paths. Those transitions now share the organization capacity transaction and enforce the configured five-active-Recruiter limit. Final-state race tests were added for direct creation, reactivation versus creation, and invitation acceptance versus direct creation. The final race-suite rerun is blocked by disposable Mongo startup in this environment; see verification results.

## 9. API/UI contract impact

- No route or response shape was added. Organization and team duplicate slugs keep a safe `409`; capacity remains a `400`; suspended/missing organizations return `403`/`404` from the shared capacity check.
- Invitation funnel keys remain `pending`, `accepted`, `expired`, `revoked`, but counts now represent the full organization instead of the recent sample. Pending excludes expired invitations; expired includes explicit expired status and pending records past expiry.
- `recentInvitations` remains bounded at 10 returned records with a deterministic tie-breaker.
- Admin activity remains paginated; count/list now share organization and deletion filters, output order is deterministic, and private audit payload fields are omitted.
- Admin Console recruiter/team membership writes now participate in the same transaction as team creation. No frontend client required a code change for these existing paths.

## 10. Query and scalability findings

- The analytics endpoint no longer transfers every organization `Job` document to Node for counts; a MongoDB `$match` plus `$facet` aggregates recruiter and status totals. Fixture reconciliation passed.
- Activity no longer builds a potentially large actor ID list from memberships and then queries audit logs by actor. It filters directly by organization and uses an allowlisted projection. Count and page filters match.
- Activity and recent-invitation ordering now have deterministic `_id` tie-breakers.
- No query-plan `explain`, demo read-only query, endpoint query-count measurement, latency benchmark, or index proposal was run. No index or performance SLA was added.
