# Tech News production configuration and operation

## Upgrade an existing installation

1. Keep the current `backend/.env`, MongoDB URI, Redis password, JWT/encryption keys and stored settings. Do not copy the example over an existing environment. This task preserved all 156 pre-existing local values and moved news assignments into one section. Every news setting has an immediate comment with units, defaults, limits, behavior and restart instructions.
2. Review the 81 ordered keys between `TECH NEWS CONFIGURATION — START/END` in `backend/.env.example`. The same keys and order occur in the local file. The catalog in `backend/src/config/newsEnvCatalog.js` is the reproducible inventory; `refresh-configuration-inventory.json` records safe local values and credential-presence booleans. No new infrastructure or paid provider is required. For another legacy deployment, back up its environment privately, then run `node backend/src/scripts/organizeNewsEnv.js` from the repository root; the script asserts that existing parsed values remain identical before writing and rejects unknown news keys.
3. Retain global `MONGODB_URI` from the existing MongoDB deployment or Atlas connection dialog. The startup connection uses **MONGODB_URI**, not the legacy `MONGO_URI`. Use the existing application database. Do not set a test URI to the application database.
4. Retain global `REDIS_URL`, or the existing `UPSTASH_REDIS_HOST`, `UPSTASH_REDIS_PORT` and `UPSTASH_REDIS_TOKEN`. Obtain the host, port and **database password** from the Upstash native Redis connection panel. Use `rediss://default:<URL-encoded-password>@<host>:<port>` for TLS. `REDIS_URL` takes precedence. REST endpoints and REST bearer tokens do not replace the native connection details. All backend processes must share this database. Governance fails closed when Redis is unavailable; MongoDB cannot substitute for distributed quotas.
5. Keep `NEWS_INGESTION_ENABLED=true` on at least one backend process and `NEWS_DISCOVERY_ENABLED=true`. The existing platform `newsEnabled` setting must also permit news. Startup starts the worker through the existing news scheduler. No deployment/process-manager manifest exists in this repository; retain the existing hosting process arrangement and restart its backend after environment/code updates. The worker polls every five seconds, wakes immediately for admitted jobs, renews a 20-second heartbeat, uses a 90-second fenced lease and a 120-second queue visibility deadline. The queue holds at most 16 queries. These are fixed implementation bounds, not missing environment variables.
6. Inspect startup validation errors rather than increasing budgets: malformed flags, out-of-range settings, invalid prewarm topics and inverted cache retention are rejected. Set a maximum of four public prewarm phrases; prewarming is optional and consumes the same global job budget as users. Disable it or lower its separate daily ceiling if user traffic needs more headroom.
7. Run `node backend/src/scripts/inspectNewsRuntime.js "EC2"` from the repository root for sanitized flags, worker heartbeat, cache settings, provider approval/restriction, current usage, exact admission reason, next eligibility and stored query check/version. This command performs no application writes or provider requests. A heartbeat is a timestamp; compare it with `checkedAt` rather than assuming any stored value means a healthy worker. Query details reflect Redis state; a missing entry can still have an unexpired MongoDB fallback. Do not interpret diagnostics as a provider call or a successful query check.
8. Run `node backend/src/scripts/ensureNewsTopicIndexes.js` for read-only inspection. The application database already had the unique cache-key index, absolute TTL index and compound topic/expiry index during this task. If another deployment lacks one, review its change process, then run the same script with `--apply` during its approved migration window. It calls `createIndexes` only; it does not synchronize/drop indexes or delete data. A conflict is an explicit migration failure, requiring operator review.
9. Deploy the built frontend through the current hosting workflow, deploy/restart the backend with the preserved environment, and check the signed-in News page. Search a public technology phrase, wait for completion, and use **Check for New Articles** after the displayed eligibility time. Verify the query's successful-check timestamp and that other backend processes see its new version. Deployment and hosted Redis write-path acceptance were not performed in this task.

## Where values come from

| Group                | How to choose or obtain values                                                                                                                                              | Required / optional                                                                                  |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Core                 | Operator feature flags; defaults enable ingestion/discovery, subject to platform settings.                                                                                  | Required for discovery.                                                                              |
| Search               | Operator result cap 1–30; manual minimum 60,000–3,600,000 ms. Start at 30 results and 60,000 ms.                                                                            | Defaults work; source limits still apply.                                                            |
| Background Workers   | Operator chooses prewarm boolean, up to four technology phrases and 0–4 jobs/day. Default is four standard topics.                                                          | Prewarm is optional.                                                                                 |
| User / Global Limits | Operator service capacity: default 12 jobs/UTC day globally, 3 new jobs/account/UTC minute and 6/account/UTC day. Existing/active jobs cost no new job credit.              | Shared across backend processes.                                                                     |
| Cache                | Operator freshness/retention policy: positive 1,800,000 ms, absolute retention 86,400,000 ms, empty-query TTL 300,000 ms and 128 memory entries by default.                 | Defaults recommended for this deployment.                                                            |
| Redis Governance     | Operator reviewed aggregate limits: HN and DEV 84/day, 2,500/month, 60,000 ms spacing; GitHub 12/day, 300/month, 300,000 ms spacing.                                        | Combined ceilings supplement adapter limits.                                                         |
| Provider Settings    | Content approval comes from the deployment's policy review; numeric budgets are operator ceilings, not upstream entitlements. Never raise a limit solely to clear a denial. | HN/DEV search are approved here; broad defaults 72/day and 2,200/month; search 12/day and 300/month. |
| Restricted Sources   | Credentials come from the provider account described below, after an appropriate production/content agreement.                                                              | Optional, unapproved and zero-budget by default.                                                     |
| Verification only    | Local/disposable test endpoints, generated namespace and explicit opt-in flags.                                                                                             | Not production dependencies. Leave endpoint and namespace values empty outside verification.         |

The catalog and immediate environment comments list the exact bounds/default for **every** key, including source-specific overrides. Daily limits reset at 00:00 UTC; monthly limits at the first day of the next UTC month. Runtime interval floors are 60,000 ms for ordinary adapters, 300,000 ms for GitHub and 600,000 ms for Lobsters. Broad HN/DEV ingestion reserves the configured search adapter's share when an aggregate budget is reduced; approval=false and zero budgets are enforced. Failed/uncertain upstream attempts still consume a reservation. Do not delete or rename existing counters to recover quota.

## Refresh states and recovery

| State / reason                                                                   | Meaning and next step                                                                                                                                                                                                                                |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Checking cache                                                                   | The short HTTP request reads bounded shared results; it does not call upstream providers.                                                                                                                                                            |
| waiting + interval/shared_interval/concurrency/shared_concurrency                | All eligible sources are temporarily blocked. No job is admitted. The response includes the earliest provider eligibility; each provider reports its own reason/time.                                                                                |
| queued / searching / processing                                                  | One shared query job exists, providers are being checked, or validated articles are being persisted. Repeated/cross-account requests reuse it. The UI preserves articles and polls at most four times, every 20 seconds.                             |
| ready                                                                            | A successful check stored matching results. Ordinary fresh-cache reads spend no provider credit.                                                                                                                                                     |
| no_newer                                                                         | A manual check completed successfully across attempted sources and added no new URLs. The UI shows “No newer articles found” and the real successful-check time.                                                                                     |
| exhausted                                                                        | A successful bounded search found no matches; the negative cache lasts the configured TTL. This does not mean the provider archive is empty.                                                                                                         |
| daily_budget / monthly_budget / shared_daily_budget / shared_monthly_budget      | Adapter or aggregate ceiling reached; wait until the exact UTC reset. Broad ingestion cannot spend reserved keyword-search headroom.                                                                                                                 |
| upstream_rate_limit / upstream_access_denied / circuit_open                      | Retry-After/reset cooldown, authentication/content denial, or repeated failures. Cooldowns can extend and are never shortened by a click. Unknown reset defaults to six hours; a circuit opens for five minutes after three failures in ten minutes. |
| discovery_daily_budget / user_discovery_budget / user_discovery_daily_budget     | Global/account job admission limit; exact UTC day or minute boundary is reported. No provider request is made.                                                                                                                                       |
| quota_store_unavailable / queue_full / worker_offline / cache_persistence_failed | Infrastructure cannot safely proceed. Restore the shared service/worker or investigate bounded persistence failure. The UI stops indefinite spinning; provider calls cannot fall back to process-local quota counters.                               |

Eligibility is conditional, not a promise of new articles: another query/worker can consume a shared slot before the next click. Manual refresh bypasses ordinary positive/negative freshness only when its own minimum interval and all current job/provider rules permit. It does not reset timestamps, quotas or cooldowns. Legacy completed states with `lastAttemptAt` remain refreshable after deployment.

## Cache and verification

Public query keys are normalized hashes. Shared snapshots contain metadata and source diagnostics, without account profiles or ranking. Memory caches are bounded and compare Redis versions; Redis state/topic/version publication is atomic and lease-fenced after MongoDB persistence. MongoDB writes reject an older attempt. Article retention is absolute and enforced by readers even before TTL deletion; empty checks have their own TTL. Publication dates are not rewritten. Query freshness and last successful check are independent of general-pool freshness. Filters, full filtered totals and server pagination run before slicing; private account ranking stays outside shared snapshots.

For disposable verification, set `NEWS_TEST_REDIS_URL` and `NEWS_TEST_MONGODB_URI` to distinct localhost instances. Remote Redis requires TLS, a different application endpoint/password and explicit `NEWS_TEST_REDIS_DISPOSABLE=true`; never use application Redis for integration writes. Optional `NEWS_TEST_BROWSER=true` enables the focused browser path after a frontend build. Optional `NEWS_TEST_LIVE_PROVIDERS=true` permits at most one live request per approved provider in the live test, only after read-only application quota preflight. Test namespaces are generated `news-test:<UUID>:` values and cleaned by exact ownership. Mongo test databases have unique names and are dropped after verification. Historical evidence from the previous implementation is retained.
