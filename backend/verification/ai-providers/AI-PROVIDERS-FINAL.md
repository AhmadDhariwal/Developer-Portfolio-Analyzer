## Architecture findings and resulting behavior

- The old chain started with Groq and included OpenRouter; environment/admin preference could change its order. The new production chain is fixed: **Gemini → OpenAI → Grok (xAI) → Anthropic**. `backend/src/config/aiProviders.js` is the single registry for adapters, endpoints, defaults and limits. `AI_PROVIDER_PRIORITY` records that order for operators; it does not permit arbitrary production reordering.
- Missing keys/models are skipped. Existing Gemini/OpenAI credentials and model settings are preserved. Environment model selections take precedence over generic admin defaults, fixing the default OpenAI admin model masking an explicitly configured environment model. Encrypted admin settings still work when no explicit environment model overrides them. No stored admin record was migrated or rewritten.
- Groq is available only when `NODE_ENV=development` and `AI_ENABLE_GROQ_DEV=true`. It is disabled in the supplied environment/example and always excluded in production, even if a legacy priority variable requests it. It is appended after the approved providers in explicitly enabled development environments.
- OpenRouter's registry/transport special case was removed after searching runtime services, controllers, models, frontend settings and scripts. No application module imports an OpenRouter adapter or depends on its response schema: all paid AI callers use the shared facade. A legacy Sprint live-verifier still lists the historical provider name; it was preserved with the frozen Sprint implementation and will report the removed provider disabled if an old key exists. Historical reports are untouched. Stored legacy admin provider names are not silently converted into another credential/provider.
- The previous manager could continue to another provider after invalid requests and gave each attempt a fresh timeout. The new facade and manager share `aiRequestBudget`: one request deadline includes cache lookup, admission, provider attempts and retry/release work. Provider caps are reduced by the remaining total time. Even an uncooperative adapter/cache cannot hold the caller indefinitely; abort signals propagate to actual transports and late results cannot be cached after cancellation.
- Each provider uses its selected primary compatible model. Explicit model lists remain configured and inventoried, but do not create an unbounded model waterfall. Default attempts are capped at four. Multi-provider failures advance once through the chain; a sole eligible provider gets at most one jittered retry on transient infrastructure errors, inside the same cap/deadline. 429 and authentication/configuration failures do not retry that provider immediately.
- A dedicated `AIProviderAdmission` Mongo model supplies shared global/provider concurrency slots, minute/day request quotas and credential/model-scoped circuits. Admission fails closed when Mongo is unavailable. Cached and deterministic results remain usable. Token-conditional lease release protects a successor; expiry recovers abandoned slots. TTL expiration is housekeeping, not the correctness mechanism. Quota reservations are conservative and are not refunded after uncertain outcomes.
- Recognized authentication/model-configuration failures open a shared circuit, avoiding repeated attempts with the same broken configuration. A changed credential/model has a different circuit identity. 429 uses the larger configured cooldown/Retry-After, bounded to one day; consecutive transient failures open the circuit, and successful recovery resets it. Circuit expiry permits recovery under the existing provider concurrency cap; it is not a single-probe half-open protocol.
- Refusal and restriction metadata is inspected **before** JSON extraction: OpenAI/xAI refusal/content filter, Gemini prompt/safety block and Anthropic refusal are terminal. Recognized plain-text/JSON refusals are also terminal. Invalid requests and ambiguous 403 responses stop the chain. Only recognized authentication/permission configuration errors may skip a broken configuration. Safety refusals never cause a different model/provider attempt.
- Transport JSON normalizes through the existing result contract: manager success `{ok, provider, model, parsed, latencyMs}`, facade JSON value or opt-in `{ok, value, provider, model, latencyMs, reason}`. OpenAI uses `max_completion_tokens`; Anthropic now honours the caller's output-token cap. Truncated/malformed output does not become a successful cache entry. Existing schema, factual, provenance and persistence checks remain in each module; syntactic JSON acceptance alone is not factual verification.

The supplied Gemini/OpenAI cooldown settings were preserved. Daily quota buckets use UTC epoch-day boundaries, independently of the display timezone. Configure limits identically on all workers and synchronize their clocks. Software request quotas do not enforce token-per-minute, account spend or provider billing limits. A failed/aborted request can still be billed; bounded fallback may call up to four providers when a module permits it. Exactly-once provider billing after a crash requires provider-side guarantees. Tune software limits below actual account allowances and configure provider-side spend controls.

Groq has a published free-plan rate-limit tier, making it a possible optional development service; free capacity is constrained and is not a production SLA or a promise that every model/request is free. See [Groq rate limits](https://console.groq.com/docs/rate-limits). Gemini limits depend on the project/model/tier and include request/token constraints: [Gemini limits](https://ai.google.dev/gemini-api/docs/rate-limits). xAI publishes per-model request/token limits: [xAI limits](https://docs.x.ai/developers/rate-limits). Check current model-specific charges and account access before activation: [OpenAI pricing](https://developers.openai.com/api/docs/pricing), [xAI pricing](https://docs.x.ai/developers/pricing), [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing). No exact price or billing total is inferred from the two synthetic checks.

Adapter behavior was checked against the [OpenAI API reference](https://developers.openai.com/api/reference/resources/chat), [xAI Chat Completions reference](https://docs.x.ai/developers/model-capabilities/legacy/chat-completions), [Gemini generation reference](https://ai.google.dev/api/generate-content?hl=en) and [Anthropic stop-reason reference](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons).
