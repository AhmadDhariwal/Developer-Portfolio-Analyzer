# Recruiter security and multi-tenancy

| Boundary           | Behavior                                                                                                                                                                                                                                                                    |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Role and tenant    | Both recruiter route families explicitly require a recruiter account and server-resolved organization. Super Admin uses its dedicated APIs.                                                                                                                                 |
| Resource ownership | Legacy and Hub recruiter job operations use organization and recruiter ownership. Match and shortlist filters apply both scope fields.                                                                                                                                      |
| Candidate consent  | User discovery requires a developer account with isPublic enabled. Organization visibility applies directly to the User query. Candidate lookup and pipeline hydration recheck visibility, including for linked legacy IDs. Portfolio artifacts require a public portfolio. |
| Inputs             | Candidate search treats metacharacters literally, and email is excluded from discovery search. Recruiter services validate resource IDs and bounded candidate lists before resource queries. Activity dates are validated.                                                  |
| Invitations        | The transaction claims a pending invitation, checks organization and team, preserves organization boundaries, creates both memberships, and invalidates old sessions for an existing account. Disabled accounts are rejected.                                               |
| Audit              | Recruiter HTTP audit events use trusted context. Successful actions with a domain audit event suppress the duplicate HTTP event. Generic recruiter audit events omit request and response payloads.                                                                         |
| Cache              | Authorization and visibility checks precede summary caching. Scope and MongoDB-derived content identity isolate cache entries and handle recovery.                                                                                                                          |

Disposable HTTP coverage exercises missing credentials, wrong role, Super Admin restrictions, two organizations, sibling recruiter access, malformed identifiers, candidate consent changes and concurrent invitation acceptance. Additional checks remain for all combinations of team changes, suspension, expired sessions and administrative mutations.
