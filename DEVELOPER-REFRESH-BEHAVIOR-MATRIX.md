# Developer refresh behavior matrix

The dependency map lists data ownership, screen entry, manual actions and caches for each module. The policies below describe the source paths reviewed for this continuation. Browser reload, hard reload and two-tab scenarios still require browser acceptance.

| Module                         | Page entry and reload                                                                                                                  | Explicit action                                                                           |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| GitHub                         | Owned saved result via POST with savedOnly; no provider request. Analyze reuses compatible accepted data.                              | Sync fetches provider evidence under a renewable owner lease.                             |
| Resume                         | Active file, library and saved analysis reads. Obsolete responses are ignored when a new upload changes the context.                   | View reuses a matching already loaded file. Analyze remains explicit.                     |
| Profile                        | Saved profile revalidation.                                                                                                            | Context writes update the selected scope.                                                 |
| Integrations                   | Persisted connections and insights.                                                                                                    | Existing provider sync workflow.                                                          |
| Skill Gap                      | Owner-scoped GitHub evidence and selected resume; deterministic analysis when eligible.                                                | Explicit analysis keeps existing AI admission, with GitHub sync owned by GitHub Analyzer. |
| Portfolio                      | The scoring endpoint fingerprints owned GitHub, resume, Skill Gap and integration inputs.                                              | Existing explicit scoring workflow.                                                       |
| Recommendations                | Revalidates saved results; derived deterministic calculations use owned GitHub. A failed read retaining previous cards displays stale. | Existing enrichment with quotas. Profile enrichment uses saved GitHub evidence.           |
| Sprint                         | Saved sprint and progress.                                                                                                             | Task changes and explicit plan actions.                                                   |
| Courses                        | Catalog and learning progress are separate.                                                                                            | Progress updates Dashboard/report state without clearing the catalog cache.               |
| Interview                      | Saved catalog and sessions.                                                                                                            | Explicit generation; existing shared maintenance lease.                                   |
| Scenario                       | Saved baseline and scenario history.                                                                                                   | Run and save hypothetical scenario explicitly.                                            |
| Jobs and News                  | Saved feeds; existing scheduled ingestion.                                                                                             | Existing bounded provider/catalog refresh controls.                                       |
| Reports                        | Saved latest and history.                                                                                                              | Existing generation workflow.                                                             |
| Notifications                  | Inbox and existing SSE.                                                                                                                | Read/delete actions.                                                                      |
| Portfolio settings and support | Owned settings and tickets; publication has separate scope.                                                                            | Explicit edits and publication.                                                           |
| Dashboard                      | Read-only summary with existing revision checks. Source and career context events share refresh scheduling.                            | Read-only revalidation.                                                                   |

Freshness presentation remains module-specific. This change set does not verify a consistent five-state experience across all screens.
