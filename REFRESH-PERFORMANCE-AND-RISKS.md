## 2. Performance, Concurrency, Rate-Limit & Cost Analysis

### 2.1 Excessive API Requests / Redundant Fetches on Navigation
- **`CoursesComponent` initial load (`course-learning.store.ts:38-46` & `coursePersonalizationService.js`)**:
  - `learning.load()` uses `expand` to paginate through **all** `/api/courses/my-learning` pages sequentially on every visit to `/app/courses`.
  - Backend `fetchCourses` always runs `resolveSkillSignals()` (3+ Mongo lookups) AND `courseCatalogSearchService.load()` before checking `courseMemoryCache` (though `courseCatalogSearchService` caches in-memory for `30s`).
- **`DashboardComponent` (`dashboard.component.ts:436-444`)**:
  - Hardcodes `forceRefresh = true`, writing `localStorage` (`60s`) on every response yet **never reading** from `localStorage`. On backend, `readStableDashboard` executes the multi-collection summary read **twice** per request to guarantee snapshot consistency (`dashboardConsistencyService.js:24-35`), meaning every route return to `/app/dashboard` performs 2 full multi-collection Mongo reads (mitigated by `ETag` `304` on HTTP-cached reloads, though still computed server-side before returning `304`).
- **`Navbar` (`navbar.ts:432-461`)**:
  - Calls public unauthenticated GitHub REST API (`https://api.github.com/users/<handle>/repos?per_page=100&sort=updated`) directly from the browser for search autocomplete (cached only in component memory for navbar lifetime), risking GitHub browser IP 60 req/hr rate limits if reloaded frequently.

### 2.2 Cache Stampede Protection (Strong vs. Missing)
- **Well-protected (singleflight + distributed lease)**: `GitHub` (`analysisJobs` + `github-save` + `lock:github_swr`), `Resume` (`analyzeInFlight` + `analyzeResumeJobs` + `resumeLease` global 8 / user 2 / file 1, joining waiters switch to `forceRefresh:false`), `Skill Gap` (`inflightSkillGapRequests` + `skillGapGovernance` 45s lease, joining waiters switch to `forceRefresh:false`), `Recommendations` (`recommendationInflight` + `recommendationGovernance` 60s lease + `recommendations:enrichment-lock`), `Courses` (`coursePoolInflight` + `courseGovernanceService` 30s pool lease + 4 YT slot leases), `Interview Prep` (`inflightRequests` + `interviewGenerationFlight` + `InterviewCoordination.runAI` lease/4 slots), `Public Portfolio` (`flights` + Redis `${key}:lock` `10s` wait `1000ms`), `Jobs` (`jobPoolCacheService.inflight` + `jobs:v2:lease:refresh` `60s`), `News` (`newsPoolService.inflight` + Redis leases `30s–120s`), `Career Sprint` (`generationInflight` + `overviewCache.pending` + `sprintAiAdmissionService` `10s` lease), `Integrations` (`IntegrationPublicSnapshot` `flights` + Mongo leases).
- **Unprotected against stampedes**: `Analysis /api/analysis/portfolio-score` (no lock, no singleflight), `Workflows /api/workflows` (no per-user dedupe, bypasses domain caches), `AdminConsoleService.getConsolePerformanceData` (expensive multi-collection aggregations with no inflight coalescing on cache miss), `SuperAdminAnalyticsService` (heavy uncached aggregations).

### 2.3 Redis Outage & Fail-Closed Behavior
- **Fail-Closed `503` on Redis outage**:
  - `Scenario Simulator` in `production` (unless `SCENARIO_LIMIT_MODE=single-instance`): `503 Shared Scenario quota service is unavailable.` (`scenarioSimulatorMiddleware.js:45-52`).
  - `Jobs Hub` manual refresh (`?refresh=true`), actions (`save`/`apply`/`hide`), and hidden-access unlock/lock: `503` (strict Redis enforcement). `GET /api/jobs` reads still succeed via local fallback limiter + L1 memory / Mongo `JobCache`.
  - `Tech News` async discovery worker: queue operations require Redis; catalog reads (`GET /api/news`, `/saved`) remain healthy via Mongo `NewsArticle`/`NewsCache`.
- **Fail-Closed `503` on Mongo governance outage**:
  - `Resume`, `Courses`, `Skill Gap`, `Recommendations`, `Career Sprint AI`, `Notifications`, `Public Portfolio`, `Interview Prep`, `Weekly Reports`, `Integrations`, `Support`.
- **Graceful Degradation on Redis outage**:
  - `GitHub`, `Resume`, `Skill Gap`, `Recommendations`, `Courses`, `Career Sprint`, `Interview Prep`, `Public Portfolio`, and `AIProviderManager` (`AIService.memoryCache` `256` entries) all continue functioning via process memory and/or MongoDB.

### 2.4 Paid AI & External API Cost Risks
- **`Weekly Reports` Cron / Worker (`weeklyReportService.js`)**: Unlike Courses/News/Jobs/Interview Maintenance, `runWeeklyReportBatch()` invokes `aiService.runAIAnalysis` across batches of users (mitigated by `signalHash` smart-skip and `ai:response` 24h Redis cache when evidence is unchanged).
- **`Recommendations` (`recommendationService.js`)**: AI enrichment is safely gated (`enabled: forceRefresh`) and limited (`5/hr`).
- **`Workflows` (`POST /api/workflows` `'deep_scan'` / `'combined'`)**: Executes `resume`, `skill_gap`, `recommendations`, and `portfolio_score` steps directly via `aiService.runAIAnalysis` bypassing each domain's Mongo `AnalysisCache` / `ResumeAnalysisCache` / admission quotas!
- **`Jobs` (`jobService.js`)**: Paid providers (`JSearch`, `Jooble`, `Adzuna`) only trigger if free sources return `< 80` jobs or explicit `platform` filter is passed, and default env daily/monthly budgets are `0` unless explicitly configured.

### 2.5 Unbounded / Long Cache TTLs & Missing Cancellation
- **`RecommendationsComponent` (`24h` `localStorage`)** & **`ResumeService` helper (`30d` `localStorage`, unused)**: `24h` browser `localStorage` survives both `F5` and `Ctrl+Shift+R`, causing multi-tab/scheduled backend changes to stay invisible until user clicks Refresh or `currentSignalHash` is updated elsewhere.
- **Request Cancellation Verification**:
  - Verified present on `CareerSprint`, `ScenarioSimulator` (`takeUntil` + `cancelScenarioCaches` on profile/account switch), `InterviewPrepService` (`epoch` + `cancel.next()` + 12s/40s timeouts), `PublicProfileService` (`cancelReads.next()`), `DashboardComponent` (`requestCancelled.next()`), `SkillGapComponent` (`unsubscribe` on `requestSubscription`), `CoursesComponent` (`takeUntilDestroyed` / cleanup).
  - `Notifications`: `NotificationService` SSE uses `AbortController` with `45s` idle timeout and clean abort on logout/destroy; `SupportService` uses `shareReplay(1)` (no auto-abort on destroy since list requests are fast/shared).

### 2.6 Missing Graceful Shutdown Cleanup (`backend/index.js:305-316`)
- `emailRetryQueueService`, `integrationSyncService`, `jobSourceSyncService`, `weeklyReportService` cron, `interviewQuestionIngestionService`, and `interviewQuestionMaintenanceService` timers/cron tasks are not stopped inside `shutdown()`, whereas `notificationRetentionService`, `notificationStreamService`, `newsIngestionScheduler`, and `courseCatalogMaintenanceService` cleanly stop.
