## 1. Startup Gate & Graceful Shutdown (`backend/index.js`)

- **`--api-only` Mode (`backend/index.js:5-8, 247-250`)**:
  - Allowed only when `NODE_ENV === 'development'`.
  - Binds HTTP listener to `'localhost'` and returns immediately at `L249`, **disabling ALL 10 background workers/schedulers, tracing, `PlatformSettings` warmup (`getSettings()`), and the `JobsHub` cache health probe**.
- **Cluster / Multi-Instance Behavior**:
  - In normal mode (`!localApiOnly`), every backend process boots **all** enabled workers/schedulers automatically (with the sole process-role switch `WEEKLY_REPORT_PROCESS_ROLE !== 'api'` for Weekly Reports at `L258`).
- **Shutdown Hook Coverage (`shutdown()`, `backend/index.js:305-316`)**:
  - Explicitly stops ONLY: `notificationRetentionService.stop()`, `notificationStreamService.stop()`, `stopNewsIngestionScheduler()`, `courseCatalogMaintenanceService.stop()`, `closeRedisCache()`, and `shutdownTracing()`.
  - Workers with **no** `stop()` call wired in `shutdown()` (timers are `.unref()`'d or stay active until process exit): `emailRetryQueueService`, `integrationSyncService`, `jobSourceSyncService`, `weeklyReportService` cron, `interviewQuestionIngestionService`, `interviewQuestionMaintenanceService`.

## 4. Interval vs. Cache TTL vs. True Data Freshness Comparison

A critical architectural distinction:

| Module | Configured Scheduler Interval | Cache TTL (Shortest -> Longest) | Effective End-User Data Freshness | Observed Job Duration |
|---|---|---|---|---|
| **Jobs Hub** | `4h` worker (`1h` min) | FE `30s` -> BE L1 `15s` -> Redis `5m` -> Mongo `36h` fresh / `7d` retain | Normal view sees data synced up to `36h` ago (`4h` typical on active worker); manual Refresh (`2/15m`) queues fresh API fetch (`60s` gate) | **NOT MEASURED** |
| **Tech News** | `1m` pool tick / `5s` search queue / `1h` adaptive eval | FE `15s` (`5s` saved) -> BE mem `5s` -> Redis `20m` pool (`30m` topic) -> Mongo `1–35d` | Broad feed updates within `5s–20m` (subject to `20m` provider spacing); topic discovery updates asynchronously within `5s` worker cycle | **NOT MEASURED** |
| **Courses** | `1h` (`:17`) audit / `1m` fCC & YT discovery | Catalog mem `30s` -> Pool mem `60s` -> Redis `15m` (**promoted `1h` in mem!**) -> Mongo `6h` | New YouTube/fCC courses appear in Mongo within ~`1m`, visible across workers within `30s`–`15m` (`1h` if `poolHash` & `catalogRevision` cached in `redisCacheService.memoryCache`) | **NOT MEASURED** |
| **Integrations** | `5m` worker poll (`30m` sync cadence) | Snapshot `5m` (`IntegrationPublicSnapshot`) | Background sync refreshes connected providers every `30m`; manual `Sync Now` updates immediately (unless manual unverified source < `5m` old) | **NOT MEASURED** |
| **Weekly Reports** | `Monday 08:00` cron (`+ 60s` standalone worker catchup) | FE `localStorage` `15m` latest / `10m` history -> Weekly Mongo snapshot | New weekly cron report appears immediately for email/SSE, **but up to `15m` stale in browser if user already opened Weekly Reports within 15m** | **NOT MEASURED** |
| **Interview Prep** | `6h` scraper ingest / `4h` seed maintenance | BE mem `30s` -> Redis `1h–24h` (revision-keyed) | Seed catalog / new questions invalidate topic cache immediately (`UUID` rotation); scraped articles stay pending review (`isApproved: false`) | **NOT MEASURED** |
| **Notifications** | `15s` SSE heartbeat / `60m` opt-in retention | FE `15s` Map | Near real-time (`1s` coalesced push via Change Stream, max `15s` reconcile fallback, or `60s` polling if SSE disconnected) | **NOT MEASURED** |
